Quick Guide — DTMF Macros

►

Each entry maps a numeric slot to a DTMF command sequence. The slot number is how the macro is referenced — by a user dialing *3<slot> on the radio, by a schedule entry, or by another macro.

Allowed characters in a command sequence:

Character(s)Meaning
0–9 * # A–DDTMF digits sent to app_rpt
p~500 ms pause (lowercase or uppercase P)
(space)Separates multiple commands in one slot

Common app_rpt commands you can put in a macro:

CommandWhat it does
*3<node>Connect to a node (transceive)
*1<node>Disconnect a specific node
*70Disconnect all linked nodes
*80System status announcement
*99Restart app_rpt (reload rpt.conf)

Example entries:

1 = *327096       ; slot 1: connect to node 27096
2 = *170 p *327096 ; slot 2: disconnect all, pause, connect 27096
3 = *70            ; slot 3: disconnect all nodes

The node stanza must have macro = {{ m }} (or the default stanza named macro) for these entries to be active.

Quick Guide — Scheduled Macros

►

Each entry runs a macro slot at a given time. The key is the macro slot number (from the node's macro stanza), and the value is a five-field cron-style time expression.

Time field order: minute   hour   day-of-month   month   day-of-week

FieldRangeExample
minute0–5930 = at :30
hour0–2306 = 6 AM
day of month1–31* = every day
month1–12* = every month
day of week0–6 (Sun=0)1 = Monday

Example entries:

1 = 00 06 * * *   ; run macro slot 1 every day at 06:00
2 = 30 18 * * 5   ; run macro slot 2 every Friday at 18:30
3 = 00 12 1 * *   ; run macro slot 3 on the 1st of each month at noon

Only plain numbers and * are supported per field — ranges (1-5), lists (1,3,5), and steps (*/2) are not supported by app_rpt and will be rejected on save. The node stanza must have scheduler = {{ s }} (or the default stanza named schedule) for entries here to fire.

Configuration Guide

      

        

          Quick fix: Run the AMI setup script on your node:

          sudo bash /opt/HenWen/ami-setup.sh

          This reads manager.conf, tests the connection, and updates the service file automatically.
        

        
Step 1 — /etc/asterisk/manager.conf must have a user stanza:

        
[general]
enabled = yes
port = 5038
bindaddr = 127.0.0.1

[admin]
secret = your_secret_here
read = system,call,log,verbose,command,agent,user,config,dtmf,reporting,cdr,dialplan
write = system,call,log,verbose,command,agent,user,config,dtmf,reporting,cdr,dialplan
permit = 127.0.0.1/255.255.255.0

        
Step 2 — Set credentials in the service file:

        
sudo nano /etc/systemd/system/HenWen.service
# Set these two Environment lines:
Environment="AMI_USER=admin"
Environment="AMI_SECRET=your_secret_here"

        
Step 3 — Apply changes:

        
sudo systemctl daemon-reload
sudo systemctl restart HenWen
sudo asterisk -rx "module reload manager"

TX Diagnostics

    
Checks everything the browser TX (transmit) button on the Kiosk needs, end to end.


    

      

        
Run Checks

        

          
        

      

      

        

          Covers TX setup (SIP credentials, PJSIP endpoint), whether this page itself is on
          a secure (HTTPS) origin, and the network/NAT layer (Apache on 443, Asterisk's
          websocket, RTP range, STUN). The network checks re-run
          tx-spike/check-ports.sh and take a few seconds — nothing
          is changed on the system.
        

        
Click Run Diagnostics to check TX readiness.

      

    


    

      
Setup Guide

      

        
TX needs HTTPS (skip if this box already has it) and the Asterisk-side PJSIP/WebRTC config, in that order:

        
sudo bash /opt/HenWen/tx-spike/setup-https.sh <hostname> <email>
sudo bash /opt/HenWen/tx-spike/apply.sh

        

          setup-https.sh requires a public hostname already pointed at this box
          and port 80 forwarded (plus your chosen HTTPS port — --port N if not
          443; --dns-manual if your ISP blocks port 80 too). No public hostname
          to point here? A third-party service that can front HTTPS for you (Tailscale Serve/Funnel,
          Cloudflare Tunnel, etc.) works too — see tx-spike/README.md for what
          it needs to proxy. Both scripts are safe to re-run.

Node ID

    
FCC-compliant repeater identification — plays your ID on key-up, every 10 min during activity, and after the transmission ends.


    

      Playback mode (below) decides where your ID actually goes. Local only reaches other connected AllStarLink nodes, but never this node's own local RF-attached repeater/controller — if this node's purpose is to be your repeater's controller, that mode alone will never put the ID out over your own RF at all. All connected links reaches your own RF equipment too, which most repeater-controller nodes need for a valid FCC ID — but it also plays out on every currently-linked node and their own equipment, which may itself be RF-connected. If another repeater happens to be linked when your ID fires, your ID goes out on their RF too, identifying a station that isn't theirs on a system they don't control. Know which mode you actually need before enabling this.

Network Ports

      

        

          The web UI's own port and the AMI (Asterisk Manager Interface) port. Both are
          written into the systemd unit file; the AMI port also has to match
          manager.conf's port = line, which
